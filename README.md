# qja1998.github.io

CatBus — 알고리즘 문제 풀이와 삽질 기록.

[Astro](https://astro.build) + [AstroPaper](https://github.com/satnaing/astro-paper) 기반.
`main`/`master` 에 push 하면 GitHub Actions 가 빌드해 GitHub Pages 로 배포한다.

## 개발

```bash
npm ci
npm run dev          # http://localhost:4321
npx astro build      # dist/ 생성
npx pagefind --site dist   # 검색 인덱스 (배포 시 Actions 가 수행)
```

## 글 쓰기

`src/content/posts/<slug>.md` 를 만든다. **파일명이 곧 URL** 이다 (`/posts/<slug>/`).

```yaml
---
title: "[BOJ] 공격 - 1430 (G4)"
author: "kwon_gi_beom"
pubDatetime: 2025-10-26T17:31:56+09:00
description: "한 줄 요약. 목록 카드와 검색 결과에 그대로 나온다."
tags: ["math", "bfs"]
categories: ["boj", "gold"]
---
```

- `pubDatetime` 은 `+09:00` 형식이어야 한다. `+0900` 은 YAML 이 날짜로 읽지 못한다.
- 이미지는 `public/posting_imgs/` 에 두고 `/posting_imgs/이름.webp` 로 참조한다.
- 수식은 `$…$` / `$$…$$` (remark-math + KaTeX).

## 임베딩 — 비슷한 글

글을 쓰거나 고친 뒤 한 번 돌리고 결과를 함께 커밋한다.

```bash
npm run embed        # src/data/embeddings.json 갱신
```

- 본문 해시가 바뀐 글만 다시 계산한다. 모델을 매번 내려받지 않으려고
  결과를 저장소에 둔다 — 빌드(CI)는 이 파일만 읽는다.
- 모델은 `Xenova/multilingual-e5-small` (384차원). 한국어·영어가 섞여 있어
  다국어 모델을 쓴다. 임베딩 입력에서 **코드블록은 뺀다** — 넣으면 문제 풀이끼리
  코드가 비슷해 전부 한 곳에 뭉친다.
- 산출물은 빌드 입력이다. 브라우저로 가는 건 고른 이웃의 제목과 링크뿐,
  벡터는 나가지 않는다.
- 쓰는 곳: 포스트 하단 `비슷한 글` (`src/components/RelatedPosts.astro`).

## 홈 카드 커버 — 문서를 들여다보는 창

커버 사진이 한 장도 없다. 그래서 **글에서 조각 하나를 골라 마크다운 그대로**
그린다. 고르는 쪽도 그리는 쪽도 그 조각이 무슨 종류인지 묻지 않는다.

**고르기** (`tools/embed.mjs`)

1. 본문을 **빈 줄과 코드 펜스로만** 자른다. 표인지 코드인지 판정하지 않는다.
2. 각 조각을 글 본문과 같은 모델로 임베딩하고 글 전체 벡터와의 코사인을 잰다.
3. 여기에 세 가지를 곱한다 — 셋 다 종류를 묻지 않는다.

| 곱하는 것 | 왜 | 식 |
|---|---|---|
| 구조 밀도 | 그냥 두면 산문이 이긴다(글의 대부분이 산문이니까) | 기호·숫자 비율, 줄 수, 줄 길이 분산 |
| 제목과 안 겹칠수록 | 제목이 이미 말한 것을 표지가 되풀이할 필요는 없다 | `0.35 + 0.65 × (1 − 제목과의 낱말 겹침)` |
| 여러 글이 안 쓸수록 | 백준 77편에 다 있는 「시간 제한」 표는 그 글에 대해 아무 말도 안 한다 | `÷ √(같은 골격을 쓰는 글 수)` |

4. 고른 조각의 **앞머리에서 여러 글이 공유하는 줄**(`import sys`,
   `input = sys.stdin.readline` …)을 걷어낸다. 글자도 숫자도 없는 줄
   (`$$`, `` ``` ``, `|---|`)은 내용이 아니라 구조이므로 건드리지 않는다.
5. 창이 휑하지 않도록 그 자리에서 **이어지는 조각을 480자까지** 더 가져온다.
   무엇이 이어지는지도 묻지 않는다 — 문서 순서 그대로다.

**그리기** (`src/utils/hero.ts` → `src/components/PostCard.astro`)

본문과 같은 마크다운 처리기(remark-math + rehype-katex + shiki)에 그대로 넘긴다.
코드는 하이라이트되고, 표는 표로, `$$`는 KaTeX 로 나온다. 커버는 항상 어두우므로
shiki 의 다크 색만 쓰고, 아래로 갈수록 흐려지며 잘린다 — 잘린 자리가 경계가
아니라 "이 아래로 이어진다" 로 읽히게 하는 게 목적이다.

결과(165편): 코드 118 · 목록 14 · 문단 11 · 표 9 · 수식 8 · 제목 4 · 인용 1.
**이 분류는 코드 어디에도 없다** — 세어 보니 그렇게 나뉜 것이다. 같은 골격을 쓰는
표지는 0편이다.

한계: 이미지는 글자를 거의 안 갖고 있어 텍스트 유사도 경쟁에서 이길 수 없다.
36편이 본문에 그림을 갖고 있지만 표지로 뽑힌 건 0편이다.

바탕색은 임베딩 공간에서 그 글이 있는 방향이다. 밝기를 고정한 채 색상환 360° 를
쓰면 따뜻한 구간이 탁해져 청록~보라 180° 만 쓰고, 0°/360° 경계에 걸친 무리가
찢기지 않도록 각도 분포에서 가장 빈 구간에서 자르고, 백준(47%)이 색상환을
독차지하지 않도록 순위와 각도를 반씩 섞는다. 홈의 분류 칩과 스펙트럼 밴드도
같은 색을 쓰므로 칩 줄이 곧 범례다.
