# qja1998.github.io

CatBus — 알고리즘 문제 풀이와 삽질 기록.

[Astro](https://astro.build) + [AstroPaper](https://github.com/satnaing/astro-paper) 기반.
`main`/`master` 에 push 하면 GitHub Actions 가 빌드해 GitHub Pages 로 배포한다.

## 개발

```bash
npm ci
npm run dev          # http://localhost:4321
npx astro build      # dist/ 생성
npx pagefind --site dist   # 검색 인덱스 (배포 시 Actions 가 수행)
```

## 글 쓰기

`src/content/posts/<slug>.md` 를 만든다. **파일명이 곧 URL** 이다 (`/posts/<slug>/`).

```yaml
---
title: "[BOJ] 공격 - 1430 (G4)"
author: "kwon_gi_beom"
pubDatetime: 2025-10-26T17:31:56+09:00
description: "한 줄 요약. 목록 카드와 검색 결과에 그대로 나온다."
tags: ["math", "bfs"]
categories: ["boj", "gold"]
---
```

- `pubDatetime` 은 `+09:00` 형식이어야 한다. `+0900` 은 YAML 이 날짜로 읽지 못한다.
- 이미지는 `public/posting_imgs/` 에 두고 `/posting_imgs/이름.webp` 로 참조한다.
- 수식은 `$…$` / `$$…$$` (remark-math + KaTeX).

## 임베딩 — 비슷한 글

글을 쓰거나 고친 뒤 한 번 돌리고 결과를 함께 커밋한다.

```bash
npm run embed        # src/data/embeddings.json 갱신
```

- 본문 해시가 바뀐 글만 다시 계산한다. 모델을 매번 내려받지 않으려고
  결과를 저장소에 둔다 — 빌드(CI)는 이 파일만 읽는다.
- 모델은 `Xenova/multilingual-e5-small` (384차원). 한국어·영어가 섞여 있어
  다국어 모델을 쓴다. 임베딩 입력에서 **코드블록은 뺀다** — 넣으면 문제 풀이끼리
  코드가 비슷해 전부 한 곳에 뭉친다.
- 산출물은 빌드 입력이다. 브라우저로 가는 건 고른 이웃의 제목과 링크뿐,
  벡터는 나가지 않는다.
- 쓰는 곳: 포스트 하단 `비슷한 글` (`src/components/RelatedPosts.astro`).

## 홈 카드 커버 — 핵심 낱말 + 의미 색

이 블로그에는 커버 사진이 없다. 그래서 커버를 글 자체에서 만든다.

- **낱말** (`keyTerms()`) — 커버에서 가장 크게. 이 글이 무엇에 관한 글인지 말한다.
- **바탕색** (`semanticColor()`) — 의미 공간에서 이 글이 있는 방향. 비슷한 글끼리
  비슷한 색이 된다. 홈의 분류 칩·스펙트럼 밴드도 같은 색을 쓰므로 칩 줄이 범례다.

낱말을 쓰는 이유: 차트(막대·파형·방사형·3차원·레이더)와 색을 다 만들어 봤지만
전부 **'이 둘이 비슷하다'** 까지만 전한다. **'이게 무슨 글이다'** 는 못 전한다.
색은 범례를 봐야 하고 이웃한 주제는 색이 붙어 구별도 안 된다.
사람에게 의미를 즉각 전하는 건 낱말이다. 차트 코드는 `coverShape.ts` 에 남겨 뒀다.

낱말 뽑는 법 (`tools/embed.mjs`) — 태그를 쓰지 않는다. 그래야 새 주제로 글을 써도
그 글의 말이 그대로 나온다.

1. 본문 **산문에서** 후보를 뽑는다(라틴 토큰, 조사를 뗀 한글 낱말, 두 낱말 묶음).
   코드까지 넣으면 `cur_w` · `bridge.append` 같은 식별자가 희귀해서 IDF 를 먹고
   1등이 된다.
2. 15% 넘는 글에 나오는 말은 이 글을 설명하지 못하므로 뺀다.
3. 후보를 같은 모델로 임베딩해 글 전체 벡터와의 코사인 × IDF 로 정렬한다.
4. 낱말이 겹치는 후보는 하나만 남기고 위에서 두 개를 쓴다. 3위부터는 잡음이다.

낱말 벡터는 글끼리 겹치므로 `src/data/.term-vectors.json` 에 캐시한다
(결과가 아니라 계산 캐시라 저장소에 넣지 않는다 — 넣으면 6MB 가 된다).

색상 배치에서 조정한 것:
- 밝기를 고정한 채 색상환 360° 를 쓰면 따뜻한 구간이 탁한 올리브가 된다
  → 청록~보라 180° 만 쓴다.
- 0°/360° 경계에 걸친 무리는 순위를 매길 때 양 끝으로 찢긴다(트러블슈팅 뭉침이
  0.99 → 0.39 였다) → 각도 분포에서 가장 빈 구간을 찾아 거기서 자른다.
- 순위로만 펴면 백준(47%)이 색상환 절반을 먹고, 각도만 쓰면 백준 77편이 한 색이
  된다 → 반씩 섞는다.
